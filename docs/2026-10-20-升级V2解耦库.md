# 升级到 V2 解耦库（v1.1 → v2.0 底座）

- 日期：2026-10-20
- 变更范围：**仅 libMcbctrl 库**（见 `libMcbctrl_HMCB_20260421/docs/2026-10-20-V2.0.1.1接收解析解耦移植.md`），
  HMCB_Qt 应用层**零代码改动**。

## 为什么应用层不用改

库对应用的唯一契约未变：

- 入口仍是 `SetMCBCommand(WPARAM, LPARAM)`（mangled `_Z13SetMCBCommandml` 已验证导出）；
- 回调仍是 `PFCALLBACK(UINT msg, WPARAM, LPARAM)`，`MCB_MSG_STATUS/MCB_MSG_DATA`
  语义与 `lParam=(nMCB<<16)+code` 编码不变；
- `McbController` 的静态 trampoline 转发路径不变——解耦发生在库内部
  （socket recv → 共享缓冲 → 解析线程 → 回调），回调仍从库工作线程触发，
  Controller 的 Queued 转发照常工作。

## 行为差异与观测点

| 项 | v1.1 库 | v2.0 库 |
|---|---|---|
| 解析位置 | socket 接收线程内联 | 独立解析线程（每 MCB 一个） |
| 高包率接收 | 解析阻塞会拖慢接收 | 接收只入缓冲，不被解析拖慢 |
| 停机 | 同步排空 | STOPOK 前解析线程排空 local（实测 <300ms，残留 ≤1 帧） |
| 新日志行 | — | `parse thread created/started/exit. recv=… parsed=…` |
| 新诊断 | — | `HMCB_LIB_DEBUG=1`：接收/解析两侧每秒速率与缓冲水位 |

## 真机验收（2026-10-20，CX1664DE @192.111.111.211）

- 60s 连续采集：每秒精确 250 包、软/硬计数全程 differ:0（零丢帧）、
  速度格 0.0640 MB/s 稳定（几何 1DM×64×2×16bit）。
- 生命周期 ×2：INITIAL→DVREADY→START→STOP→STOPOK→CLOSE→重新 INITIAL→再采集，
  解析线程重启路径正常。
- HMCB_Qt ctest 14/14 通过。
